# Why it felt automatable

- the model already knew the nodes
- the relationships already carried intent
- Pulumi already had typed resources, inputs, outputs, and invokes
- the missing piece was a translation layer between the two

<br/>

```mermaid

    A[Deployment DSL] --> B[Same deployment intent]
    C[Pulumi C#] --> B
    B --> D[Translate instead of rewrite]
```

At the same time, Pulumi already had the execution model I needed.
It had typed resources, inputs, outputs, and provider invokes.

So I did not feel like I needed a code generator in the classic sense.
I felt like I needed a translation layer that could read the model and materialize the same intent through Pulumi.

- propagates parent values into child resource arguments
- maps outputs into inputs through relationships
- supports transformers, converters, and inline pipelines

- creates relationship-resources such as role assignments
